# Decisions

Implementer-decides choices from `PLAN.md`, one line of reasoning each. Newest at the bottom.

| #   | Topic            | Decision                                                                                                                    | Why                                                                                                                         |
| --- | ---------------- | --------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | Repo shape       | One monorepo, Bun workspaces (`packages/*`, `apps/*`, `tools/*`)                                                            | Shared protocol types, one PR flow, one CI file; Bun is already the runtime for tests and the connector.                    |
| 2   | Package wiring   | Workspaces import TS source directly (`exports: ./src/index.ts`, `workspace:*`), no build step for `@agent-office/protocol` | Bun, Vite and Wrangler (esbuild) all consume TS natively; zero build orchestration.                                         |
| 3   | Connector        | Single Bun-compiled binary (`bun build --compile`, darwin-arm64/x64), runs under launchd                                    | Same TypeScript + protocol package as the server; one file to download and swap on self-update; still runs on Linux for CI. |
| 4   | Server           | Cloudflare Workers free plan + one SQLite-backed Durable Object (`office`) with WebSocket Hibernation                       | Long-lived WebSockets, free HTTPS/wss, durable SQLite for history; matches the recommendation.                              |
| 5   | Hub core         | Runtime-agnostic Hub (state, `diff()`, stats) in plain TS, wrapped by the DO and by a Bun dev harness                       | Unit tests and local e2e need no Workers runtime; the DO is a thin adapter.                                                 |
| 6   | Renderer         | PixiJS v8 + Vite, served as static assets by the Worker                                                                     | Fast WebGL sprites, good pixel-art support (nearest scaling), tiny API surface vs. a full game engine.                      |
| 7   | Schemas          | zod v4 for every wire message, discriminated unions per channel, non-throwing parsers                                       | One source of truth for runtime validation and TS types; v4 is smaller and faster.                                          |
| 8   | Lint/format      | Biome (recommended rules, 2-space, width 100)                                                                               | One fast tool for lint + format, no ESLint/Prettier config sprawl.                                                          |
| 9   | Tests            | `bun test` everywhere                                                                                                       | Built into the runtime, fast, no Jest/Vitest config.                                                                        |
| 10  | Art style        | Cozy top-down 3/4 office, 16 px tiles scaled by integers, Endesga 32 palette, characters drawn in code (paper-doll layers)  | Consistent intentional look with no asset licensing; palette constants live in `@agent-office/protocol`.                    |
| 11  | Agent colors     | Claude `#be4a2f`, Codex `#0099db`, Pi `#63c74d`, unknown `#8b9bb4` (all Endesga 32, with light/shade ramps)                 | Fixed hues from PLAN mapped to the nearest palette entries.                                                                 |
| 12  | IDs              | ULIDs (dependency-free) for envelope ids; `personId` = slug of the display name; `sessionId` = `clientId:sessionKey`        | Time-sortable ids; two laptops with the same name become one person; session ids stable across reconnects.                  |
| 13  | Avatars w/o AI   | `avatarFromSeed(name)` via FNV-1a + mulberry32; `sessionVariation(sessionKey)` for sibling tweaks                           | Deterministic on every side, so server and renderer agree without coordination.                                             |
| 14  | Extra close code | `4003` = bad message (besides 4001 bad password, 4002 too old)                                                              | Lets the connector distinguish its own bugs from auth problems.                                                             |

## Server (apps/server)

| #   | Topic                 | Decision | Why |
| --- | --------------------- | -------- | --- |
| S1  | Layering              | Pure `core/` (diff, hub, stats, genui, store, app) + thin adapters: `office.ts` (DO) and `dev/bun-server.ts` (Bun.serve + bun:sqlite) | Same logic in unit tests, wrangler dev and the Bun harness; the DO has no business logic. |
| S2  | Hub time model        | Hub never sets timers; every call takes `now`, `nextDeadline()` drives one DO alarm (only moved earlier; an early alarm just ticks and re-arms) | Deterministic tests, and alarms fire ~once per minute instead of per heartbeat. |
| S3  | Event order           | Per diff: session.ended → person.left → person.joined (with `sessions: []`) → avatar.updated → session.started → activityChanged → subagent.* | Viewers can apply events in order without special cases; joins animate first, then desks fill. |
| S4  | New session counts    | A session that appears with subagents > 0 carries the count in `session.started`; no `subagent.spawned` for it (same for ended sessions) | One event per unit *change* of an existing session; avoids puff storms on reconnect. |
| S5  | Socket close w/o bye  | Connector stays (sessions keep showing) until its 75 s liveness timeout; `bye` ends sessions immediately | Deploys/network blips close sockets; connectors reconnect within seconds, so no flicker. |
| S6  | Restart / hibernation | Structural state (connectors, sessions, people) persisted as one kv row only when its fingerprint changes; socket bindings live in `serializeAttachment`; restore gives connectors a fresh 75 s window | Wakes and redeploys emit no spurious leave/join; heartbeats and activity changes cause zero storage writes. |
| S7  | Takeover              | Hello with a known clientId on a new socket rebinds it; messages on the old socket get close 1000 "superseded" | Handles half-open sockets after laptop sleep. |
| S8  | History rows          | One row per viewer event except `session.activityChanged`; `person` = personId; ended/subagent rows carry agent/project from the previous state | Stats never need activity; skipping it keeps SQLite row writes far below the free 100k/day. |
| S9  | Stats                 | Heatmap weekday (0 = Mon) × hour in `OFFICE_TIMEZONE`; "most parallel" = per-person sweep of started/ended rows (clamped at 0, reset on person.left); top 5 per board; shape in `@agent-office/protocol` `StatsResponse` | Cheap to compute on request from a few thousand rows; shared type for the web page. |
| S10 | GenUI providers       | `off` (seeded), `anthropic` (raw fetch to Messages API, forced `set_avatar` tool whose input_schema is the catalog, model `GENUI_MODEL` or `claude-haiku-4-5`), `jev` = Vercel AI Gateway OpenAI-compatible `/v1/chat/completions` with `response_format: json_schema` (`AI_GATEWAY_API_KEY`, default model `openai/gpt-4o-mini`) | Keeps "jev" dependency-free: we use the gateway directly instead of the `typesafe-ai/jev` library; any gateway model id works via GENUI_MODEL. |
| S11 | GenUI caching/cap     | Avatar cached per person in SQLite under key `provider:hash(name+description)`; job only when that key changes (join with new description); daily counter `genui.calls.<UTC date>`; failures/cap/invalid output store the seeded look under `key:fallback` so the next join retries | Near-zero cost, bounded, and a transient error doesn't pin a person to the seeded look forever. |
| S12 | Password              | `CONNECTOR_PASSWORD` secret; unset → every connector rejected (4001) unless `DEV_MODE=1` (then "devpass"); `bun run dev` copies `.dev.vars.example` → `.dev.vars` | Safe default in prod, zero-setup locally. |
| S13 | Snapshots             | PNG magic check, ≤ 300 KB, stored as BLOB in DO SQLite, 1 upload / 10 min server-side (429 + Retry-After); `Authorization: Bearer <CONNECTOR_PASSWORD>` bypasses the limit (simulator/screenshots); empty-office skipping is the recorder's job | A week of 15-min frames at ~50–150 KB fits easily in DO storage; no R2 needed. |
| S14 | install.sh            | Bundled into the Worker as a wrangler `Text` module from `apps/connector/install.sh`; the literal `__AGENT_OFFICE_SERVER__` is replaced with the request origin | One-liner install works from whatever host serves it, no hard-coded URL. |
| S15 | Static assets         | `[assets]` from `../web/dist`, `run_worker_first` for /ws/*, /api/*, /healthz, /install.sh; default `auto-trailing-slash` maps /stats → stats.html | Assets are served without invoking the Worker (free, not counted as requests). |
| S16 | Extra protocol fields | Additive: `office.snapshot.data.timezone?` (day/night) and `packages/protocol/src/api.ts` (`HistoryRow`, `StatsResponse`, `SnapshotList`) | Web and simulator share the HTTP shapes with the server. |
| S17 | Request budget        | Estimate for 10 connectors, 10 h/day: heartbeats 10 × 1,200 = 12k msgs + ~20k change snapshots = ~32k incoming WS msgs ÷ 20 ≈ 1.6k billed requests; alarms ≈ 600–800; WS upgrades, viewer connects, /api calls and 40–96 snapshot posts ≈ 300–500 → **≈ 2.5–3.5k requests/day** (≈ 4–5k if laptops stay on 24 h). Ping/pong auto-responses are free; outgoing broadcasts are not billed; static assets are free | Comfortably within "a few thousand/day" on the shared 100k free plan. |

## Connector (apps/connector)

| #   | Topic                 | Decision | Why |
| --- | --------------------- | -------- | --- |
| C1  | Runtime deps          | Zero beyond `@agent-office/protocol` (Bun WebSocket/fetch/crypto/spawn, hand-rolled flat TOML) | Smallest binary surface; nothing to audit or break on cross-compile. |
| C2  | Process detection     | `ps -axo pid=,args=` on macOS (not `comm`), `/proc/*/cmdline` on Linux; match argv0 or `node/bun <script>` against claude/codex/pi | Claude/Pi often run as `node …/cli.js` and the native Claude binary's file name is its version number. |
| C3  | Liveness              | Live = Claude pid file with a running claude pid, OR newest transcript whose folder/cwd matches a running agent's cwd (lsof, cached per pid), OR transcript < 90 s old while any process of that agent runs; the first two stay live as `idle` | Pid files/cwd give exact process ties and real idle; the mtime rule keeps it working without either. |
| C4  | Test mode             | `--assume-processes` / `AGENT_OFFICE_ASSUME_PROCESSES=1` = every agent running and every pid-file pid alive; `--home`/`AGENT_OFFICE_HOME` replaces ~ and then ignores CLAUDE_CONFIG_DIR/CODEX_HOME/PI_CODING_AGENT_DIR | Fixtures run on Linux CI; a fixture run can never pick up the real ~/.claude via a stray env var. |
| C5  | Activity extras       | Assistant text with no end marker + 30 s silence → `waiting`; "[Request interrupted by user" / Codex task_complete/turn_aborted / Pi aborted → `waiting`; TodoWrite/Task/MCP tools → `thinking`; subagent count forced to 0 when idle | Not every agent version writes stop reasons; idle desks shouldn't show busy helpers. |
| C6  | Session key           | `sha256(clientId:agent:rawId)` → 16 hex chars | Salted per laptop so keys can't be joined across machines or reversed to session ids. |
| C7  | Codex scan scope      | Only the two newest `sessions/YYYY/MM/DD` folders | Constant cost per poll, independent of the date; a resumed week-old rollout is missed (acceptable). |
| C8  | Claude cwd fallback   | Pid file cwd → transcript `cwd` field → greedy filesystem-guided decode of the folder name; `agent-*.jsonl` next to sessions ignored | Basename is right even for hyphenated folder names; legacy sidechains aren't separate sessions. |
| C9  | Self-update safety    | Download → temp file next to the binary → run `<tmp> version` → require strictly newer → atomic rename → exit(0) (launchd KeepAlive restarts); failed version not retried for 10 min; dev builds and `bun src/main.ts` never update; `AGENT_OFFICE_NO_UPDATE=1` disables | A broken or stale (CDN-cached) asset can never replace a working binary or cause a restart loop. |
| C10 | GitHub poll           | Every 5 min: REST `releases/latest` tag_name, falling back to the `/releases/latest` redirect `Location` | Unauthenticated API is 60 req/h per IP; ~10 laptops on one office NAT would exceed it. |
| C11 | Below min version     | Stay connected but send no snapshots until the update succeeds | PLAN: "update before sending anything else"; the server would reject the old shape anyway. |
| C12 | Bad password (4001)   | Retry after 5 min, no exponential hammering; 4002 → update then normal backoff | A typo shouldn't flood the server; too-old fixes itself. |
| C13 | Config/status         | `configure` subcommand writes the TOML (0600, atomic) so install.sh never quotes TOML; daemon writes `status.json` each poll, `status` treats it as stale after 10 s or a dead pid | Shell quoting bugs avoided; `status` works without IPC. |
| C14 | install.sh            | POSIX sh, prompts via /dev/tty (stdin is the curl pipe), env `AO_*` for non-interactive, accepts both `__AGENT_OFFICE_SERVER__` (what the server substitutes) and `__SERVER_URL__` placeholders, installs to ~/.local/bin, Rosetta-aware arch detection | Works as `curl … | sh`, in CI, and with either placeholder convention. |
| C15 | launchd               | `~/Library/LaunchAgents/dev.agentoffice.connector.plist`, RunAtLoad + KeepAlive + ThrottleInterval 5, stdout/err → `~/Library/Logs/agent-office.log`, `launchctl bootout` then `bootstrap gui/<uid>` | Re-running the installer is idempotent; exit(0) after an update restarts within ~5 s. |
| C16 | Linux                 | Builds and runs (for tests); no service manager integration, logs to stdout | Team is macOS-only. |

### Connector: unbuilt

- Optional Claude Code hook (`~/.claude/settings.json` pinging the daemon on session start/end) is not built; 2 s file polling is fast enough.
- launchd/`install-service`/`uninstall` and the darwin binaries are untested on a real Mac (cross-compiled from Linux; arm64 binary carries an ad-hoc LC_CODE_SIGNATURE).

## Simulator (tools/sim)

| #    | Topic              | Decision | Why |
| ---- | ------------------ | -------- | --- |
| SIM1 | Script model       | Scenarios are generators of `Step`s (`connect/bye/drop/reconnect/start/end/activity/subagents/wait/settled`) over a pure `World`, driven by `seededRandom("sim:<scenario>:<seed>")`; the runner applies each action before pulling the next | Same seed = same script; `dryRun()` replays it on a virtual clock with no network, so determinism and schema validity are unit-tested. |
| SIM2 | Real protocol      | One `FakeConnector` per laptop over a real WebSocket: hello → wait for welcomed → debounced snapshots (500 ms ÷ speed) + 30 s heartbeats (real time, never scaled) → bye; every outgoing message is `ConnectorToServer.safeParse`d and the sim throws on its own bugs | Exercises exactly what the real connector does; liveness timers on the server stay meaningful at any `--speed`. |
| SIM3 | Ids                | `clientId = sim-<12 hex>`, `sessionKey` = 16 hex, both from the seed; a person's second laptop is a second clientId with the same name | Two laptops collapse into one person server-side, like real use. |
| SIM4 | "settled"          | At the scenario's `settled` step pending snapshots are flushed, then `GET /api/state` is polled until every online sim session is present with the same agent/activity/subagents (foreign/leftover people ignored, 8 s timeout → warning) | Screenshot scripts and e2e can `await sim.settled` and know the server, not just the sim, is there. |
| SIM5 | Scenarios          | `busy` is hand-picked (Anna…Felix, Martin on two laptops, Claude with 8 subagents, Lena waiting, all four agent kinds) and holds still; `stress` = 12 people / 30 sessions + a change every 80–400 ms; `join` = busy + one new person every ~8 s; `live` (default) = staggered joins, Markov-chain activities, subagent ramps up to 8, session churn, one laptop dropped without bye at step 15; `--chaos` adds drops, reconnects, bye + rejoin and rapid flips | Screenshot states are stable and recognisable; free-running modes cover the edge cases the hub must survive. |
| SIM6 | Backfill           | `generateWeek()` = 7 full days + today up to now, in Europe/Vienna local hours: ~85% weekday attendance 8–19 h with a lunch dip, 15% weekend pokes, night-owl blocks 21–01 h, per-person agent preference and 1–4 max parallel sessions, Claude subagent bursts (sometimes 8); rows posted in 5k chunks | Fills every heatmap row and every leaderboard with plausible numbers. |
| SIM7 | Snapshot frames    | Own 60-line PNG encoder (RGB8, filter 0, `node:zlib` deflate, CRC32) drawing a 192×120 pixel office that fills up and empties with a day→night sky; uploaded with Bearer (no rate limit) | No image dependency; frames are ~1 KB and visibly change in the timelapse. Server stamps upload time, so all frames of one run share ~the same minute. |
| SIM8 | Fixture writer     | Writes 2 Claude (pid files + subagent bursts incl. `workflows/`), 1 Codex, 1 Pi transcript to `mkdtemp()` and appends one line every 3 s ÷ speed; `--spawn-connector` runs the real connector with `AGENT_OFFICE_CONFIG_DIR` inside the temp home and `AGENT_OFFICE_NO_UPDATE=1` | The real detectors run end to end without touching the user's config or self-updating; temp dir is left for inspection. |
